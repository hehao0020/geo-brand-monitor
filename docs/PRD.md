# GEO Brand Monitor｜产品需求与迭代记录

## 为什么做

讨论“品牌在 AI 回答里有没有被提到”时，手工复制几个回答很容易漏掉失败请求，也容易把一次字面出现说成推荐或正面口碑。我先把一个更窄的问题做成脚本：给定一组问题，逐题请求模型，记录完整回答是否包含指定品牌词，再导出可复核的表格。

## 第一版的工作流

脚本默认顺序询问 3 个不带品牌词的情感咨询问题。每题独立对话，返回后检查完整正常回答是否包含“维情”。结果按题保留模型、时间、回答摘要和状态，通过 CSV 导出；每完成一题就保存，避免中途失败时丢掉已取得的结果。

## 判断规则要先说清

Positive 只代表字面命中，即使回答是“不推荐维情”也会命中；Missed 是正常回答未命中；请求失败、空回答或截断归为 Error，不能算作未提及。带品牌的问题另行标记，不进入“无品牌提示样本提及率”。这个工具测的是指定问题下的字面提及，不是完整 GEO 效果，也不是对示例品牌的评价。

## 处理使用中的问题

为了让报表可复核，脚本保留错误行，设置超时和有限重试，并对 CSV 中可能被表格软件当成公式的文本做转义。示例文件明确标为模拟数据。当前仓库已完成离线测试；README 记录开发环境尚未做真实 API 密钥联调，因此不能把示例结果写成实际监测结论。

## 下一步

先用真实请求检查接口与报表口径，再决定是否扩大问题样本、加入多次重复测量。若以后要比较品牌表现，还需固定提问、模型版本、采样时间和失败处理；不能把几条回答推断为整体市场排名。
